# Competition-readiness backlog

Scope: the reusable FRC platform needed to build robot logic reliably: actuation safety, transport, runtime/API contracts, sensing, deployment and diagnostics. Game strategy, shot timing, mechanism coordination rules and additional autonomous routines are not readiness requirements here.

This is an **open-work list**, not a changelog. Completed work and its reasoning remain in `git log`; measurements and bench observations are recorded, dated, in [docs/BENCH_RESULTS.md](docs/BENCH_RESULTS.md), and an entry links to them instead of repeating them. Remove an item only after its acceptance check passes; a passing existing suite does not close a newly identified coverage gap. Physical acceptance follows [docs/BRINGUP.md](docs/BRINGUP.md).

Entry form: `- [ ] **ID — the problem, in one line.**` then at most about four lines: what is wrong and where (file or symbol); the one piece of evidence that matters, or a link to its dated section in the results record; `OWNER DECISION:` with the options when a person must decide; and `Close when:` the complete acceptance check. No measurement narrative and no history; a long entry is trimmed when it is next touched.

## Physical and deployment qualification gates

These are separate from software fixes, not evidence that a failure already exists. Agents must not change physical CAN IDs or set `commissioned = true`.

Use the one-Kraken bench ([docs/BENCH.md](docs/BENCH.md), config `bench/`) for link/stop/timing qualification before the robot exists; it cannot qualify a full CAN bus, cameras or the drivetrain. Run `session_report --strict` on bench sessions; `NOT MEASURED` is not a pass.

- [ ] **FIELD-1 — Network, electrical configuration and commissioning.** Verify coprocessor/RIO addressing, field bundle selection, CAN IDs, encoder offsets, inversion and controller limits against the real robot. A responsible human commissions only after restrained disabled/enable tests; update configuration golden checks alongside deliberate hardware changes.
- [ ] **FIELD-2 — Independent stop and fault measurements.** Measure DS disable/e-stop, companion stop/stall, Ethernet removal, RIO cold reboot, single Talon/CANcoder loss and total bus loss. Confirm affected-output/dependency isolation and safe fresh recovery. Measure voltage/current or independent motion/power evidence, not merely requested neutral or invalid feedback. Include PWM zero versus pulse-loss behavior and persisted-config boot restoration. Include a hung RoboRIO loop thread (no `Gateway::Tick`): whether TalonFX outputs go neutral on their own (one-shot control expiry) and what DIO and PWM outputs hold.
- [ ] **FIELD-3 — Full-bus load and realtime tails.** On the actual coprocessor/RIO, record CAN utilization, per-signal ages, hardware gaps, command latency, loop lateness, callback duration and watchdog crossings under intended load, Python GC, disabled neutral refresh and reset restoration. Qualify achieved signal rates rather than assuming the requested rates. Desktop measurements are not Mini acceptance evidence; callback duration differs from dispatch lateness.
- [ ] **FIELD-4 — Camera qualification and independent pose accuracy.** Set stable device IDs (currently empty), measured intrinsics/distortion/mounts, actual exposure/readout/timestamp corrections and uncertainty from residuals. Check cold start, USB reconnect, surveyed positions, motion and single-tag heavy tails. Compare fused and odometry-only performance, including heading. Qualify mechanically safe degraded-module driving separately from algebraic observability. The 2026 robot's autonomous gates on `localized` (REQ-SAFE-34 in its repository's catalogue) with no stated pose accuracy behind it: state the accuracy autonomous needs. Close when: each camera passes these checks on the robot and the accuracy autonomous needs is stated and met.
- [ ] **FIELD-5 — Real boot service and rollback.** Build/test on the deployment Mini, install and boot without login as the actual account, verify log permissions/realtime scheduling/descendant cleanup and exercise rollback plus activation. Linux systemd watchdog and macOS launchd are different: `KeepAlive` restarts exits but does not detect a hung launcher. Establish an accepted hung-supervisor recovery policy on the chosen host.
- [ ] **FIELD-6 — Remaining platform coverage.** The enabled WPILib RoboRIO simulator is verified headless on macOS (WPILib 2026, Phoenix 26.3): `./sim.sh --headless --mode-schedule ... --joystick-schedule ...` drives teleop from a scripted stick and runs autonomous to its pose, and every disable neutralizes. Remaining: which macOS SDK GradleRIO requires. Under WPILib, simulated cameras get no truth (only the physics sim gateway publishes `/sim/state`), so pose there is seed plus odometry; if camera coverage under WPILib is ever needed, a `field_truth` sim node integrating `/hw/state` is the option.
