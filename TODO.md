# Competition-readiness backlog

Scope: the reusable FRC platform needed to build robot logic reliably: actuation safety, transport, runtime/API contracts, sensing, deployment and diagnostics. Game strategy, shot timing, mechanism coordination rules and additional autonomous routines are not readiness requirements here.

This is an **open-work list**, not a changelog. Completed work and its reasoning remain in `git log`. Remove an item only after its acceptance check passes; a passing existing suite does not close a newly identified coverage gap. Physical acceptance follows [docs/BRINGUP.md](docs/BRINGUP.md).

Entry form: `**ID — the problem, in one line.**` then what is wrong and where, with the evidence (file, commit or CI run), and `Close when:` the acceptance check. Reasoning and history stay in commit messages; a long entry is trimmed when it is next touched.

- [ ] **RT-5 — The RoboRIO loop's realtime scheduling and its watchdog are unmeasured.** The loop (`Robot.cpp`) enforces the command timeout; it runs at `SCHED_FIFO` 10 with `SCHED_RESET_ON_FORK`, below the kernel's interrupt threads (15) and the watchdog (30), raising itself only once `LoopWatchdog::Start` has returned a kernel-confirmed `SCHED_FIFO` priority above 10 (default scheduling otherwise, while `/home/lvuser/talos_loop_default_sched` exists at program start, or on a refusal; the start line says which), and sleeps to absolute deadlines with `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME)`, yielding 500 µs after an overrun (`LoopSchedule.h`). `LoopWatchdog` (`SCHED_FIFO` 30) neutralizes every output once a command in force outlives its expiry plus two loop periods without a tick, issuing `NeutralOut` from its own thread on the evidence of Phoenix 6's per-device control mutex (`ParentDevice::_controlReqLck`), not a written CTRE guarantee. Neither that mutex nor the HAL DIO mutex inherits priority, so a device lock held by a thread that is not running (the loop behind a thread above 10; a default-scheduled vendor thread behind the loop) blocks the watchdog there. No worst-case stop time is stated for a hung RoboRIO loop or a dead main processor, so REQ-SAFE-25 has no number to test against: state one.
