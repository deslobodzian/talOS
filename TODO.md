# Competition-readiness backlog

Scope: the reusable FRC platform needed to build robot logic reliably: actuation safety, transport, runtime/API contracts, sensing, deployment and diagnostics. Game strategy, shot timing, mechanism coordination rules and additional autonomous routines are not readiness requirements here.

This is an **open-work list**, not a changelog. Completed work and its reasoning remain in `git log`. Remove an item only after its acceptance check passes; a passing existing suite does not close a newly identified coverage gap. Physical acceptance follows [docs/BRINGUP.md](docs/BRINGUP.md).

## Open software items

- [ ] **TELEMETRY-1 — Preserve telemetry headroom.** Review the configured exclusions before adding state scalars. The telemetry constructor enforces the value-frame budget; transport limits live in [docs/DATA_FLOW.md](docs/DATA_FLOW.md).
- [ ] **TIME-3 — Tick-time target age is not recorded.** `session_report` measures target receipt age for MESSAGE dispatches, not the selected target's age at a consumer tick. Add per-tick evidence before claiming tick-time target-age acceptance.
- [ ] **POSE-1 — Make the GTSAM `factor_graph` backend the default.** `configuration/subsystems/pose_estimator.toml` selects `kalman`; `factor_graph` is to become the default. `accuracy_test` already gates both backends on identical replays, and the node tests cover GTSAM failure containment and relocalization at the 1.5 s lag. Remaining before the switch: measure the worst-case `update()` duration (odometry plus four camera observations) on the deployment Mac mini within the 20 ms period, with `bazel run //2026-robot/main_processor/pose_estimator:update_benchmark` ([what it measures](2026-robot/main_processor/pose_estimator/README.md#update-benchmark)), which `tools/mac_qualify.sh` runs with `--backend both`. On a Linux Ryzen 9 7950X3D desktop its default run measured `factor_graph` p99.9 0.37 ms, max 1.7–1.8 ms; `kalman` max 0.3 ms.
- [ ] **MAC-1 — Build and run the full suite on macOS.** The RTMS process-identity check has a macOS branch (`sysctl` `KERN_PROC_PID` start time in `talOS/rtms/rtms.cc`) and durable writes use `F_FULLFSYNC` (`talOS/process/durable_sync.h`); only the macOS CI job compiles them, and the Mac mini is the deployment host. Also confirm INC-3's restart latency there, and measure a Python node's spawn-to-registry-row time from a cold boot: its module imports run before it registers, against the 5 s startup grace (Linux: 152–169 ms cold, 77–82 ms warm for `pose_estimator`). `tools/mac_qualify.sh` runs the build, the suite and both measurements ([bring-up](docs/BRINGUP.md#network-and-mini-build)).

- [ ] **PLATFORM-1 — Decide the control and camera host from measurements.** Every open incident (INC-3, INC-5, INC-6) is macOS-only, and macOS cannot set a camera's exposure duration (`avfoundation_source.mm` applies only continuous auto exposure, so `exposure_ms` is ignored and arena auto exposure blurs tags in motion). Run MAC-1/FIELD-3 on the Mini; if per-node loop lateness does not hold a 5 ms period with margin, move control nodes (and capture, unless a UVC control path is added) to a Linux coprocessor. Accept on recorded lateness tails and a captured frame at the configured exposure.
- [ ] **TIME-4 — One timeout policy.** The bridge neutralizes a subsystem after `2 × period_us` of silence (10 ms for drivetrain/shooter, `talOS/bridge/node.cc`), independent of `command_timeout_us`; one late tick brakes the drivetrain for a gap's length. Derive the bridge owner timeout from `command_timeout_us`, never exceeding it. Accept on a test where a node misses one tick without a neutral merge, and a silent node still goes neutral within the documented bound.
- [ ] **TIME-5 — Clock-offset validity flips about once a second.** `ClockOffsetEstimator` expires its kept exchange at 1 s and replaces it only after expiry or with a smaller RTT, so States between expiry and the next exchange read `accuracy_valid() == false`, and drivetrain odometry goes invalid for ~4 ticks. Replace the kept exchange before it expires. Accept on a test with the real 5 ms State / 20 ms exchange interleaving showing no validity gap.
- [ ] **POSE-2 — The pose seed is alliance-agnostic yet counts as localized.** `pose_estimator.py` trusts `initial_*` (2, 2, 0) as `localized` on a disabled first DS view, and autonomous drives on `localized` alone; on red (or any placement off the seed) auto plans from a pose meters and π off. Make the seed per alliance and trusted only once the alliance is known (re-decided while disabled). Accept on a node test: red alliance, no camera evidence, estimator output equals the red-flipped seed.
- [ ] **POSE-3 — Camera observations are dropped between estimator ticks.** Cameras publish every frame (60 fps) and the estimator reads latest-value at 50 Hz: ~17% of observations are lost uncounted and an invalid frame can overwrite a valid one. Deliver observations in sequence and fuse all of them each tick. Accept on a test with two observations per tick, both fused.
- [ ] **DRIVE-1 — Acceleration limit is applied in the robot frame.** `drivetrain.h` slew-limits robot-frame speeds, so translating while rotating collapses speed (4 m/s at 6 rad/s limits to ~1.3 m/s) and curves the path. Limit in the field frame. Accept on a test translating at constant field velocity while rotating.
- [ ] **DRIVE-2 — Steer feedback is not validated.** `geometry.h` checks the steer encoder id only when `feedback = RemoteCANcoder`; a steer motor with default `Rotor` feedback passes startup and kinematics use rotor-relative angles. Require `RemoteCANcoder` for steer motors. Accept on a config test that refuses it.
- [ ] **DRIVE-3 — Modules re-steer on heading-hold noise.** The swerve hold-angle threshold is 1e-6 m/s, so heading-hold corrections of ~1e-4 rad/s steer every module to its rotation angle when the driver stops. Scale the threshold to max wheel speed. Accept on a test where sub-threshold rotation holds module angles.
- [ ] **AUTO-1 — Mid-auto disable/re-enable restarts the routine and re-fires the preload.** Decide and implement whether a new generation inside one autonomous period resumes or restarts; at least never re-fire a fired preload in the same match.
- [ ] **API-1 — Motor commands outside `update()` pulse.** `node.h` allows commands from `every()` and callbacks, but the flush runs after `update()` and clears every set flag, so a 20 ms `every()` on a 5 ms node drives a 25% duty cycle. Reject device setters outside `update()` in C++ and Python. Accept on a test that a setter in `every()` throws.
- [ ] **API-2 — `Motor::rezero` is not tied to the hardware frame.** The offset lives in node memory: lost on node restart (elevator drives into its stop) and kept across a device or RoboRIO reset. Move zeroing into the gateway, or clear the offset on a boot change and expose whether a zero is held.
- [ ] **API-3 — Python sends zero-fill omitted fields.** `_messages.py` defaults missing fields to 0, so a target missing a field actuates with it at zero; C++ requires every field. Require every field. Accept on a test that an omitted field raises.
- [ ] **API-4 — `talos.cpp_node` loads a second copy of the framework.** Shared C++ nodes statically link talOS node/devices and run against `libtalos_node.so`'s `Node::Impl`: duplicated statics, and `type_index` extension lookups that can miss on macOS. Link against the one shared framework or run the node binary instead.
- [ ] **LAUNCH-1 — No single-instance lock.** A second launcher (DEPLOYMENT.md "run by hand") `shm_unlink`s every live topic; later restarts in the running session attach to segments nobody shares. On Linux `SO_REUSEADDR` also lets a second bridge bind the RIO port. Take an exclusive lock per shm namespace; default `reuse_address` off. Accept on a test that a second launch is refused.
- [ ] **LAUNCH-2 — An unopenable or full registry crash-loops every node.** Nodes deliberately run without a registry row, but the launcher kills unregistered nodes after the startup grace; a registry created by another user (0644, lock in sticky `/tmp`) or full of SIGKILLed rows (freed only by heartbeat age) restarts the whole roster forever. The launcher creates the registry with the service user's mode, and stale rows of dead pids are reclaimed at once. Accept on tests for both.
- [ ] **LAUNCH-3 — Shutdown restart race and config holes.** A node killed by `systemctl stop`'s SIGTERM can be restarted during shutdown; `controller_address` accepts a hostname that the bridge then cannot parse; retention keys read with `value_or` ignore wrong types; port flags are unchecked; `max_restarts = 0` disables critical-node restarts.
- [ ] **LAUNCH-4 — Serial probes and polled reaping.** Startup probes binaries one by one (twice for graph readers) and reaping polls every 20 ms; probe in parallel and reap on SIGCHLD.
- [ ] **LOG-1 — Log writers inherit the loop's `SCHED_FIFO` on Linux and poll at 1 kHz.** `ConfigureRealtime` runs before `LogWriter::start()` creates its thread. Start the writer as `SCHED_OTHER` and wake it on submission.
- [ ] **LOG-2 — The per-node log cap keeps the session's head.** Every node gets an equal share and capture stops at it; a robot powered on in queueing records the idle period and loses the match. Keep the tail (rotate) and weight shares by rate. Measure with `session_report` on a 10-minute bench session.
- [ ] **LOG-3 — Manifests between start and end are not synced.** Power loss ends every match; sync lifecycle and DS-mode manifests off the loop.
- [ ] **TELEMETRY-2 — A stalled Studio stops telemetry for every reader.** `/talos/telemetry` is `drop_newest` and the Studio bridge reads in sequence, so a stopped bridge refuses further frames. Overwrite for the viewer stream, or read latest. The bridge should also wait for and re-attach the telemetry segment instead of throwing.
- [ ] **VISION-1 — Capture delivers stale frames and hides drops.** Two-buffer pools plus a pending slot make the worker process the older frame while the source drops the newest uncounted (`dropped_frames()` is never read). One newest-wins triple buffer per camera, all drops counted in `VisionStatus`.
- [ ] **VISION-2 — Camera failures are silent.** No connection callback is registered and open failures are swallowed; log each transition once. Cap reconnect backoff near 1 s. Replace the `use_count()` buffer-reuse race with an explicit free list.
- [ ] **VISION-3 — UVC timestamp correction.** uvcvideo SOE stamps are host arrival times; `CaptureMidpoint` moves them later by exposure/2 and never applies `latency_offset_us` to SOE/EOF. Apply the per-camera offset to every stamp kind.
- [ ] **RIO-1 — Startup config restore blocks robot-code start.** `Robot.cpp` restores the persisted config through synchronous `Reconfigure` before `HAL_ObserveUserProgramStarting()`; a mid-match reboot with dead devices stays dead for seconds per device. Restore asynchronously; fsync the persisted config.
- [ ] **RIO-2 — The RIO applies every queued command.** After a stall the backlog is applied back-to-back as CAN bursts; keep the newest only. Frame header and config chunks rely on native endianness despite the protocol README; encode explicitly.
- [ ] **CI-1 — CI runs only on `main` and PRs.** Run on `hardening/**` and `feature/**` pushes; run the sanitizer matrix on macOS; tag fixed-port tests `exclusive` (or bind port 0); diff-test checked-in Studio bindings against the genrule.
- [ ] **CI-2 — No soak or chaos coverage.** Add a job running the sim graph for minutes while SIGKILLing and SIGSTOPping nodes (including Studio and telemetry), asserting request gaps and neutral-on-stale.
- [ ] **SIMPLE-1 — Remove code production does not use.** RTMS counted/closing segment lifetimes and publisher reclaim (session-owned only in production), the unused zero-copy `RTMSQueue::read()`, the duplicate `ChassisTarget`, module offsets copied into `pose_estimator.toml`, and test/Studio special cases in `Supervise`.

## Unresolved incidents — investigate, do not declare fixed by a rerun

- [ ] **INC-1 — Attribute tracked Python package truncation.** **Incident; cause unknown.** Earlier runs observed zero-byte `talOS/python/talos/__init__.py` files. macOS CI run 42717213161 (commit `5a86bac`) failed every Python test outside `talOS/python` with `module 'talos' has no attribute ...` while `talos.testing` still imported from `talOS/python/talos/`, the symptom of an empty `__init__.py`; the next run passed with no Python change. Preserve write/truncate process/path/inode evidence during affected runs. The Linux and macOS CI build jobs make tracked files read-only before tests and afterward, even when tests fail, fail on any modified tracked or untracked file. Close only after attribution and a workflow regression; do not infer the writer from a passing rerun.
- [ ] **INC-2 — Confirm the Phoenix simulator stall fix in CI.** **Cause established.** Phoenix's desktop simulator serves every simulated device from one thread, which also rewrites each device's `ctre_sim/*.dat` in the working directory on every config write. While Gradle wrote the other build variant to the same disk, a rewrite blocked that thread for up to hundreds of milliseconds: configure requests failed (TxFailed/RxTimeout), feedback went stale and `Configure()` left devices unavailable (CI runs 42718398981, 42762211224, 42769978513, 42775301670). A disk write load reproduces this locally; the same load with that directory in RAM does not. `PhoenixBackend_test` now keeps simulator state in a fresh `/dev/shm` directory and bounds each wait for configured, fresh, neutral devices (`AwaitReady`, whose failure names each device and its state). Close once CI runs that include the fix pass the RIO adapter job; an `AwaitReady` failure there is a recurrence. Linux success does not establish macOS SDK/toolchain readiness.
- [ ] **INC-3 — Critical-node restart latency on macOS.** **Incident.** In the macOS rerun of CI run 42720554711 (job 129517143967), `match_rehearsal_test` failed: the SIGKILLed drivetrain restarted (restart_count 1) but sent no `/hw/request/drivetrain` within the 300 ms the driver stays frozen, so the stale-lane check had nothing to examine. Linux runs pass; the Linux per-stage SIGKILL-to-first-request breakdown, idle and under a disk write load, is in [restart latency](talOS/launcher/README.md#restart-latency). The macOS cause is not established: the deployment host is a Mac mini, so measure those stages there, also while nodes write their event logs to the same disk (`tools/mac_qualify.sh` runs `//talOS/launcher:restart_latency` idle and with `--disk-load 8`), before widening the window; the frozen producer must stay below the 500 ms stall floor.
- [ ] **INC-5 — Probes exit 127 on macOS for binaries that exist.** **Incident; cause unknown.** macOS CI run 42785663001 (job 129726105082, commit `1b8ff7f`) failed `supervision_test`'s `SessionsAreIsolatedAndCleanOnlyOwnedDirs`: the `alpha` stub's `--describe` probe exited 127 (`no describe_version field; the binary did not answer --describe; exit code 127`), while the next session's stubs, written the same way, answered. The first attempt of run 42720554711 (job 129513115928, commit `b578f62`) failed `//2026-robot/main_processor/configuration:graph_test` the same way for `front_left_camera`. Linux runs have not shown it. The supervision test log has no `execv failed` line, which the probe's child then printed to it before exiting 127 on a failed exec; its other exits with 127 before the exec (`setpgid`, the parent check, the guardian fork, the stdout redirect) printed nothing. The child now reports the step that failed and its errno to the launcher (all but the parent check, which fails only once the launcher is gone), so a recurrence names its cause in the graph error and the launcher's log, and an exit 127 without such a report came from the program after its exec. Close only once a recurrence is attributed and fixed; a passing rerun is not evidence.
- [ ] **INC-6 — Hardware-request output gaps above 30 ms on macOS CI.** **Incident; cause unknown.** `startup_test` and `match_rehearsal_test` require recorded `/hw/request` (or bridge `/hw/command`) rows at most 30 ms apart inside checked windows. macOS CI runs 42775301670 (gaps 43.8 and 46.9 ms) and 42796457757 (39.5 and 38.7 ms) failed it; Linux runs and other macOS runs pass. Requests are due every 5 ms and the command timeout is 100 ms, so these gaps are not unsafe, but whether ticks or their recording were late on that host is not established. On the robot such a gap also exceeds the bridge's 2 × period owner timeout and brakes the drivetrain for its length (TIME-4). Measure per-node loop lateness on the Mac mini (FIELD-3) before treating it as runner noise; do not widen the 30 ms bound without that evidence.

## Physical and deployment qualification gates

These are separate from software fixes, not evidence that a failure already exists. Agents must not change physical CAN IDs or set `commissioned = true`.

Use the one-Kraken bench ([docs/BENCH.md](docs/BENCH.md), config `bench/`) for link/stop/timing qualification before the robot exists; it cannot qualify a full CAN bus, cameras or the drivetrain. Run `session_report --strict` on bench sessions; `NOT MEASURED` is not a pass.

- [ ] **FIELD-1 — Network, electrical configuration and commissioning.** Verify coprocessor/RIO addressing, field bundle selection, CAN IDs, encoder offsets, inversion and controller limits against the real robot. A responsible human commissions only after restrained disabled/enable tests; update configuration golden checks alongside deliberate hardware changes.
- [ ] **FIELD-2 — Independent stop and fault measurements.** Measure DS disable/e-stop, companion stop/stall, Ethernet removal, RIO cold reboot, single Talon/CANcoder loss and total bus loss. Confirm affected-output/dependency isolation and safe fresh recovery. Measure voltage/current or independent motion/power evidence, not merely requested neutral or invalid feedback. Include PWM zero versus pulse-loss behavior and persisted-config boot restoration.
- [ ] **FIELD-3 — Full-bus load and realtime tails.** On the actual coprocessor/RIO, record CAN utilization, per-signal ages, hardware gaps, command latency, loop lateness, callback duration and watchdog crossings under intended load, Python GC, disabled neutral refresh and reset restoration. Qualify achieved signal rates rather than assuming the requested rates. Desktop measurements are not Mini acceptance evidence; callback duration differs from dispatch lateness.
- [ ] **FIELD-4 — Camera qualification and independent pose accuracy.** Set stable device IDs (currently empty), measured intrinsics/distortion/mounts, actual exposure/readout/timestamp corrections and uncertainty from residuals. Check cold start, USB reconnect, surveyed positions, motion and single-tag heavy tails. Compare fused and odometry-only performance, including heading. Qualify mechanically safe degraded-module driving separately from algebraic observability.
- [ ] **FIELD-5 — Real boot service and rollback.** Build/test on the deployment Mini, install and boot without login as the actual account, verify log permissions/realtime scheduling/descendant cleanup and exercise rollback plus activation. Linux systemd watchdog and macOS launchd are different: `KeepAlive` restarts exits but does not detect a hung launcher. Establish an accepted hung-supervisor recovery policy on the chosen host.
- [ ] **FIELD-6 — Enabled WPILib and platform coverage.** Exercise the enabled WPILib RoboRIO simulator path, not only the lightweight gateway or disabled GUI startup. Verify GradleRIO with the required macOS SDK if that is a supported development host. Test `tools/setup.ps1` install mode on a clean supported Windows/WSL machine if Windows remains supported; `-Check` alone is not installation evidence.
